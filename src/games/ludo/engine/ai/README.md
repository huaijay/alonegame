# 飞行棋 AI

## 搜索契约

`chooseMove(state, dice, options)` 保持原有入口与候选解释字段。搜索采用六面等概率的 Expectimax / Max-n：每位玩家在自己的回合选择使自己收益最大的行动。它适用于两到四位各自争胜的玩家，不假设对手会帮助根玩家，也不把其余玩家合并成一个对手联盟。

- `depth` 是最多继续搜索的掷骰次数；掷六追加也消耗一层。
- 每次先为全部合法根候选计算静态估值，再从一层起迭代加深。只有全部根候选都完成才提交这一层。
- 节点或时间预算耗尽时，返回上一完整层。`Decision.depth` 是实际完成深度，`requestedDepth` 是请求深度，`interrupted` 表示未达到请求深度。
- `nodes` 统计后续搜索访问次数，含叶子、终局和缓存命中；不含根候选静态估值。节点数严格不超过 `nodeBudget`。
- 零时间或零节点预算仍返回合法的完整静态候选列表。`budgetMs` 控制递归搜索；固定的入口估值、JavaScript 调度与垃圾回收不能作硬实时保证。
- 骰子必须是 1–6 的整数；深度、节点预算必须是非负安全整数，时间预算必须是非负有限数。非法参数抛出 `RangeError`。
- 已终局或没有合法行动时返回 `null`。

同分容差为 `1e-9`。内部按飞机原位置升序选取同分行动，根层按飞机编号打破平局。这使等价飞机重新编号时不受浮点末位误差影响。所有根候选仍保留真实编号，便于动画和解释面板使用。

## 性能结构

搜索递归使用可撤销的局部状态和逐层复用的捕获记录，不生成动画步骤；`finally` 保证预算中断时也还原状态。根候选仍使用正式 `applyMove` 结算。

- `rules.landingPosition` 是唯一的最终落点规则，正式动画与搜索查表共同使用。
- 内部合并同位置飞机的等价行动；同一骰子节点中，无合法行动的骰面共用一次跳过回合的结果。
- 置换表按剩余深度分层，键包含当前玩家、连续六点次数和各玩家排序后的飞机位置。每次决策最多保存 32,768 个内部节点，不缓存低收益的叶子节点。
- 座位在一次决策内固定；累计掷骰次数与完成顺序不影响未来合法行动，因而不进入缓存键。
- `createEvaluator()` 为一次决策创建独立工作区。叶子复用其数组和棋盘索引，返回的收益向量保持独立，能够安全放入缓存。

## 估值依据

评估先收集所有玩家的棋盘特征，再计算各自收益，避免为每位玩家重复扫描棋盘。`evaluateAll`、`evaluate` 与 `breakdownOf(...).total` 使用一致的分项计算。

1. **推进与捷径**：倒序动态规划计算一架飞机到终点的期望掷骰次数，包括等待起飞、超点停留、同色跳跃和飞行。推进与捷径分项共同表示剩余成本。
2. **终点协同**：四架飞机的终点状态采用 2,401 项查表，精确处理单方多架飞机共享骰面时的最优剩余掷骰成本。混合局面仅对终点子集做启发式校正。
3. **捕获压力**：枚举真实最终落点；只踩最终格，起飞也可捕获，同格敌机一起损失。每位攻击方每个骰子只能选择一个落点，互斥行动不会重复累计；等值不同落点均分。
4. **竞争收益**：对手的基础收益取平均后折算，避免参与人数变化造成对手权重成倍增长。
5. **终局**：胜者为 `+1_000_000`，其他玩家为 `-1_000_000`，解释分项也返回相同总分。

这些分数用于比较行动，不是胜率。单架期望、混合残局校正及多人捕获压力仍有启发式成分；多个对手对同一飞机的联合威胁没有被当作精确概率模型。

## 验证与复现

在项目根目录运行（验证环境为 Node 24，无新增依赖）：

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm bench:ai:budgets
pnpm bench:ai --depth 2 --rounds 15 --out .ai-work/benchmark-depth2.json
pnpm bench:ai --depth 3 --rounds 15 --out .ai-work/benchmark-depth3.json
```

测试以独立无缓存 Max-n 穷举检查全部候选价值，覆盖预算中断、冻结输入、置换、连续六点、无行动、最大捕获恢复、真实规则捕获概率、旧规则落点快照和残局动态规划。

基准同时比较正式搜索与使用相同新版估值的直接 Max-n 枚举。若存在 `.ai-work/original/game/ai/expectimax.ts`，还会对比修改前原版。原版与新版的收益模型和节点计数口径不同，不能把其节点数字直接当成同口径吞吐率。

原版快照存在时，可用固定种子交换算法座位做对局检查：

```sh
pnpm bench:ai --depth 2 --skip-benchmark --match-pairs 30 --out .ai-work/paired-matches.json
pnpm bench:ai --depth 2 --skip-benchmark --match-players 4 --match-pairs 20 --out .ai-work/four-player-matches.json
```

`--match-pairs` 保留双人模式的参数名；多人模式下表示种子组数，每组轮换新版所在的全部座位，其余玩家使用原版。

对局样本只说明给定规则、种子和预算下的表现，不等于 Elo，也不保证所有局面都选出全局最优行动。
